- The Sandcastle planner no longer picks the least-blocked issue when nothing is eligible. A plan lists the issues to work on and, separately, every blocked issue with the open issues blocking it; the plan schema refuses a plan without that list, an issue both selected and blocked, a selected issue that names blockers, and empty, malformed, repeated or self-referencing blockers, before any worker starts. A declared blocked issue gets no sandbox or agent. An empty queue still completes (exit 0); a run left only with blocked issues ends blocked (exit 2) and names each issue and its blockers; blocked issues beside failed or held ones leave the run incomplete. Each new plan replaces earlier blocked results, so an issue a later plan no longer lists stops counting, while an issue already failed, held or merged keeps that outcome when a later plan declares it blocked, and the schema reports problems in both lists together (S10, audit finding A11).
