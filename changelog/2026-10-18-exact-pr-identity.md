- `npm run pr` hands off only the pull request that is exactly what it pushed. It takes one GitHub destination from origin and refuses unless origin has exactly one fetch URL and one push URL, both for that repository. Every `gh` call names that host or repository, so `GH_REPO` and `GH_HOST` cannot redirect it. It reuses or creates a pull request only when GitHub reports it open, in that repository, into main, from the same branch and repository and at the checked SHA, and it ignores fork PRs, including deleted forks. Any mismatch, several open pull requests or a malformed answer refuses or fails, and anything after the push says the commit is already pushed and that a rerun reuses it. `npm run sandcastle:afk` comments only with that exact pull request, looked up in the named repository and host.
