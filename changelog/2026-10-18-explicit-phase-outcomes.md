- The Sandcastle loop records an explicit outcome per issue (`scripts/sandcastle/run-result.ts`): no work, failed in a named phase, held, integrated or not integrated. The reviewer is read-only and must end with a `<review>` verdict naming the candidate's full SHA; only a passing verdict for that exact, unchanged commit reaches the merger, and a failed, missing, malformed or stale verdict, or a reviewer that commits, holds the issue for a fresh review. After the merger the coordinator checks that the branch holds each reviewed commit and that no issue branch moved. A run is complete (exit 0) only when the queue drains with nothing failed, held or unmerged; otherwise it is incomplete or failed (exit 2) and names each issue, including all-failed sandbox creation, the 10-round limit, and planner or merger failures, which no longer crash the loop. `npm run sandcastle:afk` treats the loop's exit 2 as incomplete: it still lands what the branch holds after its own checks, then exits 2 (S09, audit finding A10).
