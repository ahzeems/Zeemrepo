- Sandcastle issues can now be resumed after a crash or a failed step without repeating finished work (S17). `scripts/sandcastle/run-state.ts` keeps one versioned state file per issue in a private host directory (`$XDG_STATE_HOME/zeemrepo/run-state`), saved by temporary file and rename and refused, but kept, when malformed, foreign, loosely held or of another version. `scripts/sandcastle/recovery.ts` resumes verification, publication and notification for unchanged inputs (task, base and exact artifact) and starts over when they change, keeping the old state aside. Each remote write is recorded as attempted first and reconciled on retry: publication reuses the exact open pull request, and `scripts/sandcastle/notifications.ts` posts an issue comment only when no comment from the same `gh` login carries its hidden marker. Failed verification holds an issue, and any unpublished issue leaves the run incomplete with exit 2. `run-result.ts` gains the settled `published` outcome. Nothing public calls recovery yet; S18 wires it in.
