- Sandcastle's coordinator can now run inside one disposable container (S14). `scripts/sandcastle/isolated-run.ts` pins the base SHA and the tooling commit, launches a container with S12's flags plus memory, CPU and process limits (refused unless `docker inspect` shows them and no mount, privilege or credential), copies in only the tooling tree, a bundle of the base and the run spec, and runs `scripts/sandcastle/guest-runner.ts` there: the actual coordinator with the SDK's `noSandbox()` provider, so its agents and the SDK's Git cleanup run inside the boundary. Docker calls pass only an allowlist of the launcher's own subcommands and options, so none can hand the guest environment. A timed-out or interrupted run is killed inside the container and still exported; artifacts come back bounded and go through S13 quarantine, and the result is never verified or published. `npm run sandbox:smoke` now also runs a real-container fake-agent control (`isolated-run-smoke.ts`): a positive run and a hung run that must keep its committed work. The public `sandcastle` commands are unchanged until S18.
